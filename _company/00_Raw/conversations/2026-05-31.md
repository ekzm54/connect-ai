### 2.1. 기술 스택 (Technology Stack)

| 영역 | 기술 스택 | 선정 이유 |
| :--- | :--- | :--- |
| **언어** | **Kotlin** | 간결성, 안정성, Jetpack Compose 지원 등 최신 안드로이드 개발 표준. |
| **UI/UX** | **Jetpack Compose** | 선언형 UI 방식으로, UI 코드의 재사용성과 유지보수성이 극대화됨. |
| **아키텍처** | **MVVM (Model-View-ViewModel)** | 비즈니스 로직(VM)과 UI(View)를 분리하여 테스트 용이성 및 확장성을 확보. |
| **상태 관리** | **Kotlin Flow / StateFlow** | 데이터 흐름을 반응형(Reactive)으로 관리하여 UI와 비즈니스 로직 간의 동기화 문제를 최소화. |

| **백엔드** | **Firebase/AWS Game Backend** | 실시간 데이터 동기화 및 사용자 인증(Auth) 처리에 특화된 클라우드 서비스 사용. |

### 2.2. 모듈 구조 (Module Structure)

프로젝트를 기능 단위로 분리하여 모듈화합니다. 이는 대규모 코드베이스에서 독립적인 개발 및 테스트를 가능하게 합니다.

1.  **`:app` (Presentation Layer):** 메인 활동(Activity) 및 UI 로직을 포함합니다.
2.  **`:domain` (Business Logic):** 게임의 핵심 규칙(예: 승리 조건 계산, 카드 조합 유효성 검사)이 정의됩니다. 이 모듈은 UI나 DB에 의존하지 않습니다.
3.  **`:data` (Repository Layer):** 데이터의 출처(Source)를 추상화합니다. 네트워크 API 통신과 로컬 DB 접근을 담당하며, **Repository Pattern**을 적용합니다.
4.  **`:ui-card` (UI Component):** 카드 컴포넌트, 보드 컴포넌트 등 재사용 가능한 UI 요소를 정의합니다.
5.  **`:network` (Networking Module):** Retrofit 인터페이스 및 API 응답/요청 DTO를 정의합니다.

## 3. 🧩 핵심 컴포넌트 및 로직 설계

### 3.1. 카드 객체 모델 (`Card Model`)

| 속성 | 타입 | 설명 |
| :--- | :--- | :--- |
| `cardId` | String | 고유 식별자 (예: "A_RED_001") |
| `suit` | Enum | 무늬 (Heart, Diamond, Spade, Club) |
| `rank` | Enum | 숫자/문자 (2 ~ A, J, Q, K) |
| `value` | Int | 게임 규칙에 따른 점수 값 (예: A=11점) |
| `isFaceUp` | Boolean | 현재 앞면이 공개되었는지 여부 |

### 3.2. 게임 상태 관리 (`Game State`)

게임의 모든 상태는 단일한 **`GameState`** 데이터 클래스로 정의하고, 이 객체가 ViewModel을 통해 Flow로 노출되어야 합니다.

```kotlin
data class GameState(
    val currentRound: Int,
    val activePlayerId: String,
    val playerHands: Map<String, List<Card>>, // 플레이어별 카드 묶음
    val boardCards: List<Card>,              // 중앙에 깔린 카드 목록
    val scoreTracker: Map<String, Int>,      // 플레이어별 현재 점수
    val isGameOver: Boolean
)
```

### 3.3. 핵심 로직: `GameRuleEngine` (Domain Layer)

이 클래스는 게임의 '규칙' 그 자체를 담당하며, **상태 변경의 유효성**을 검증하는 단일 진실 공급원(Single Source of Truth) 역할을 해야 합니다.

*   **`validateMove(gameState: GameState, move: Move): ValidationResult`**: 플레이어가 시도한 행동이 규칙에 맞는지 검사합니다. (예: "현재 턴이 아닌데 카드를 내려고 시도함" $\rightarrow$ `InvalidMoveException` 발생)
*   **`calculateNextState(currentState: GameState, move: Move): GameState`**: 유효한 이동이 발생했을 때, 다음 상태의 `GameState`를 계산하여 반환합니다.

```kotlin
// Card.kt
data class Card(
    val suit: Suit,
    val rank: Rank,
    val value: Int // 숫자 카드 값 (2-10)
) {
    companion object {
        // 덱 생성 함수 (52장)
        fun createDeck(): List<Card> {
            val suits = Suit.values().toList()
            val ranks = Rank.values().toList()
            return mutableListOf<Card>().apply {
                for (suit in suits) {
                    for (rank in ranks) {
                        add(Card(suit, rank, rank.value))
                    }
                }
            }.shuffled() // 덱 생성 후 셔플
        }
    }
}

// Player.kt
data class Player(
    val name: String,
    var hand: List<Card> = emptyList(),
    var score: Int = 0
)

// GameState.kt
data class GameState(
    val players: List<Player>,
    val discardPile: List<Card>,
    val currentPlayerIndex: Int,
    val isGameOver: Boolean = false
```

#### 3.2. Domain 계층 (GameEngine - 핵심 규칙 엔진)

```kotlin
// GameEngine.kt
class GameEngine {
    private var deck: List<Card> = emptyList()
    private var gameState: GameState

    companion object {
        // 초기 게임 상태 설정
        fun initializeGame(playerNames: List<String>): GameEngine {
            val deck = Card.createDeck()
            val players = playerNames.map { Player(it) }
            
            // 1. 덱 생성 및 셔플
            val engine = GameEngine()
            engine.deck = deck
            
            // 2. 딜링 (각 플레이어에게 5장씩, 중앙에 덱 남김)
            val initialHands = mutableListOf<Player>()
            for (i in 0 until players.size) {
                val hand = deck.take(5).shuffled().take(5)
                initialHands.add(players[i].copy(hand = hand))
            }
            
            // 3. 초기 게임 상태 설정 (간소화)
            engine.gameState = GameState(
                players = initialHands,
                discardPile = emptyList(),
                currentPlayerIndex = 0
            )
            return engine
        }
    }

    /**
     * 턴 진행: 현재 플레이어의 액션을 처리하고 게임 상태를 업데이트합니다.
     * @param actionCardIndex 현재 플레이어가 내고자 하는 손 카드 인덱스
     * @return 업데이트된 GameState
     */
    fun processTurn(actionCardIndex: Int): GameState {
        if (gameState.isGameOver) throw IllegalStateException("게임이 종료되었습니다.")

        val currentPlayer = gameState.players[gameState.currentPlayerIndex]
        val cardToPlay = currentPlayer.hand.getOrNull(actionCardIndex) ?: throw IllegalArgumentException("유효하지 않은 카드 인덱스입니다.")

        // 1. 카드 플레이 로직 (예: 무늬 일치, 숫자 순서 등 게임 규칙 적용)
        // TODO: 여기에 실제 게임 규칙(예: '이 카드는 무늬가 같아야 한다')을 검증하는 로직을 추가해야 합니다.
        if (!isValidPlay(cardToPlay)) {
            throw IllegalStateException("규칙 위반: 플레이할 수 없는 카드입니다.")
        }
        
        // 2. 상태 업데이트
        val newHands = gameState.players.toMutableList()
        newHands[gameState.currentPlayerIndex] = currentPlayer.copy(
            hand = currentPlayer.hand.toMutableList().apply { removeAt(actionCardIndex) }
        )
        
        // 3. 턴 넘기기 및 승리 판정
        val nextIndex = (gameState.currentPlayerIndex + 1) % gameState.players.size
        
        val nextState = gameState.copy(
            players = newHands,
            currentPlayerIndex = nextIndex,
            // TODO: 승리 조건 체크 로직 추가
        )
        
        return nextState
    }

    /**
     * 게임 규칙 검증을 담당하는 핵심 함수
     */
    private fun isValidPlay(card: Card): Boolean {
        // 이 함수가 게임의 모든 규칙을 담고 있습니다.
        // 예시: "현재 중앙에 공개된 카드가 무늬가 같다면, 플레이하는 카드도 같은 무늬여야 한다."
        return true // 임시로 항상 true 반환
    }
}
```

#### 3.3. ViewModel 계층 (상태 관리 및 비즈니스 로직 연결)

```kotlin
// GameViewModel.kt
class GameViewModel : ViewModel() {
    private val _gameState = MutableStateFlow<GameState>(GameState(emptyList(), emptyList(), -1))
    val gameState: StateFlow<GameState> = _gameState

    private val gameEngine = GameEngine()

    fun initializeGame(playerNames: List<String>) {
        // 1. 엔진 초기화 및 상태 설정
        val initialEngine = GameEngine.initializeGame(playerNames)
        _gameState.value = initialEngine.gameState
    }

    /**
     * 사용자가 '카드 플레이' 버튼을 눌렀을 때 호출되는 함수
     * @param cardIndex 플레이할 카드의 인덱스
     */
    fun onPlayCard(cardIndex: Int) {
        try {
            // 2. GameEngine을 통해 상태 변경을 시도
            val nextState = gameEngine.processTurn(cardIndex)
            
            // 3. 상태를 View에 발행
            _gameState.value = nextState
            
        } catch (e: IllegalStateException) {
            // 사용자에게 에러 메시지 표시 (View Layer에서 처리)
            println("게임 오류: ${e.message}")
        } catch (e: Exception) {
            println("예상치 못한 오류: ${e.message}")
        }
    }
}
```

```kotlin
            val suits = Suit.values().toList()
            val ranks = Rank.values().toList()
            return mutableListOf<Card>().apply {
                for (suit in suits) {
                    for (rank in ranks) {
                        add(Card(suit, rank, rank.value))
                    }
                }
            }.shuffled() // 덱 생성 후 셔플
        }
    }
}

// Player.kt
data class Player(
    val name: String,
    var hand: List<Card> = emptyList(),
    var score: Int = 0
)

// GameState.kt
data class GameState(
    val players: List<Player>,
    val discardPile: List<Card>,
    val currentPlayerIndex: Int,
    val isGameOver: Boolean = false
)
```

```kotlin
// GameEngine.kt
class GameEngine {
    private var deck: List<Card> = emptyList()
    private var gameState: GameState

    companion object {
        // 초기 게임 상태 설정
        fun initializeGame(playerNames: List<String>): GameEngine {
            val deck = Card.createDeck()
            val players = playerNames.map { Player(it) }
            
            // 1. 덱 생성 및 셔플
            val engine = GameEngine()
            engine.deck = deck
            
            // 2. 딜링 (각 플레이어에게 5장씩, 중앙에 덱 남김)
            val initialHands = mutableListOf<Player>()
            for (i in 0 until players.size) {
                val hand = deck.take(5).shuffled().take(5)
                initialHands.add(players[i].copy(hand = hand))
            }
            
            // 3. 초기 게임 상태 설정 (간소화)
            engine.gameState = GameState(
                players = initialHands,
                discardPile = emptyList(),
                currentPlayerIndex = 0
            )
            return engine
        }
    }

    /**
     * 턴 진행: 현재 플레이어의 액션을 처리하고 게임 상태를 업데이트합니다.
     * @param actionCardIndex 현재 플레이어가 내고자 하는 손 카드 인덱스
     * @return 업데이트된 GameState
     */
    fun processTurn(actionCardIndex: Int): GameState {
        if (gameState.isGameOver) throw IllegalStateException("게임이 종료되었습니다.")

        val currentPlayer = gameState.players[gameState.currentPlayerIndex]
        val cardToPlay = currentPlayer.hand.getOrNull(actionCardIndex) ?: throw IllegalArgumentException("유효하지 않은 카드 인덱스입니다.")

        // 1. 카드 플레이 로직 (예: 무늬 일치, 숫자 순서 등 게임 규칙 적용)

        if (!isValidPlay(cardToPlay)) {
            throw IllegalStateException("규칙 위반: 플레이할 수 없는 카드입니다.")
        }
        
        // 2. 상태 업데이트
        val newHands = gameState.players.toMutableList()
        newHands[gameState.currentPlayerIndex] = currentPlayer.copy(
            hand = currentPlayer.hand.toMutableList().apply { removeAt(actionCardIndex) }
        )
        
        // 3. 턴 넘기기 및 승리 판정
        val nextIndex = (gameState.currentPlayerIndex + 1) % gameState.players.size
        
        val nextState = gameState.copy(
            players = newHands,
            currentPlayerIndex = nextIndex,
            // TODO: 승리 조건 체크 로직 추가
        )
        
        return nextState
    }

    /**
     * 게임 규칙 검증을 담당하는 핵심 함수
     */
    private fun isValidPlay(card: Card): Boolean {
        // 이 함수가 게임의 모든 규칙을 담고 있습니다.
        // 예시: "현재 중앙에 공개된 카드가 무늬가 같다면, 플레이하는 카드도 같은 무늬여야 한다."
        return true // 임시로 항상 true 반환
    }
}
```

#### 3.3. ViewModel 계층 (상태 관리 및 비즈니스 로직 연결)

```kotlin
// GameViewModel.kt
class GameViewModel : ViewModel() {
    private val _gameState = MutableStateFlow<GameState>(GameState(emptyList(), emptyList(), -1))
    val gameState: StateFlow<GameState> = _gameState

    private val gameEngine = GameEngine()

    fun initializeGame(playerNames: List<String>) {
        // 1. 엔진 초기화 및 상태 설정
        val initialEngine = GameEngine.initializeGame(playerNames)
        _gameState.value = initialEngine.gameState
    }

    /**
     * 사용자가 '카드 플레이' 버튼을 눌렀을 때 호출되는 함수
     * @param cardIndex 플레이할 카드의 인덱스
     */
    fun onPlayCard(cardIndex: Int) {
        try {
            // 2. GameEngine을 통해 상태 변경을 시도
            val nextState = gameEngine.processTurn(cardIndex)
            
            // 3. 상태를 View에 발행
            _gameState.value = nextState
            
        } catch (e: IllegalStateException) {
            // 사용자에게 에러 메시지 표시 (View Layer에서 처리)
            println("게임 오류: ${e.message}")
        } catch (e: Exception) {
            println("예상치 못한 오류: ${e.message}")
        }
    }
}
```

### 🔍 1. 가장 중요한 주제: '도구'가 아닌 '시스템'을 판매하라 (Systemization)

**❌ 흔한 실수:** "이 툴(Tool)을 사용해서 매출이 올랐어요." (도구 중심 서술)
**✅ 시장이 원하는 서술:** "이 툴을 활용하여 [A] → [B] → [C]의 **자동화된 프로세스**를 구축했고, 그 결과 매출이 올랐어요." (시스템 중심 서술)

**💡 인사이트:**
현재 시장은 개별 솔루션(Tool)의 홍수 속에서 **'어떻게 이들을 연결하여 효율을 극대화했는가'**에 가장 큰 가치를 둡니다. 고객은 단일한 솔루션을 사는 것이 아니라, **반복 가능한 성공 공식(System)**을 구매하고자 합니다.

**✨ 케이스 스터디 적용 방법:**
* **Before & After 구조 강화:** 'Before'는 무질서한 프로세스(Pain Point)를 보여주고, 'After'는 이 Pain Point를 해결하는 **전체적인 작업 흐름도(Workflow Diagram)**를 제시해야 합니다.
* **핵심 문구:** "우리는 단순히 마케팅을 했다" 대신, **"우리는 [데이터 수집] → [AI 분석] → [개인화된 메시지 발송]의 3단계 자동화 사이클을 구축했다."**와 같이 프로세스를 명시하세요.

---

### 📈 2. 차별화된 성공 지표: '매출액' 대신 '시간 효율성'을 측정하라 (Efficiency Metric)

**❌ 흔한 실수:** "매출이 300% 증가했습니다." (결과 지표만 제시)
**✅ 시장이 원하는 서술:** "기존에 30시간 걸리던 업무를 3시간으로 단축하여, **팀이 확보한 추가 업무 시간(Time Saving)**을 다른 고부가가치 활동에 투입했습니다." (비용 절감 및 시간 가치 제시)

**💡 인사이트:**
특히 중소기업 및 B2B 고객들은 **'돈을 아끼는 것'**과 **'시간을 버는 것'**에 극도로 민감합니다. 단순히 매출 증가는 이미 많은 경쟁자가 주장하는 수치입니다. 당신의 솔루션이 절감해주는 **'노동 시간'**이나 **'의사 결정에 소요되는 시간'**을 구체적인 수치(Man-Hour)로 환산하여 제시하는 것이 더 강력한 설득력을 갖습니다.

**✨ 케이스 스터디 적용 방법:**
* **비용-시간 분석 도입:** "이전에는 A 작업을 위해 월 500만원의 인건비가 들었으나, 저희 솔루션 도입 후 이 비용이 100만원으로 줄었습니다."와 같이 **직접적인 비용 절감액**을 강조하세요.
* **KPI 확장:** 매출(Revenue) 외에 **운영 비용(OpEx) 절감액, 직원 만족도(Employee Satisfaction)** 등 비재무적 지표를 함께 제시하여 다각적인 성공을 증명해야 합니다.

### 🧠 3. 심리적 트리거: '나만 아는 비밀'을 공유하라 (Proprietary Knowledge)

**💡 인사이트:**
고객들은 '솔루션' 자체보다, **그 솔루션을 활용하기 위해 필요했던 '숨겨진 지식'이나 '검증된 방법론'**에 돈을 지불할 의향이 높습니다. 즉, 당신의 솔루션이 **'만능 열쇠'**가 아니라, **'최상급의 지식을 구현하는 강력한 도구'**처럼 포지셔닝해야 합니다.

**✨ 케이스 스터디 적용 방법:**
* **가설 제시:** 성공 사례의 서두에 "저희는 ~~라는 가설을 세웠고, 이 솔루션으로 검증했습니다"라는 문장을 삽입하여, 당신들이 **'사고하는 과정'**을 함께 보여주세요.
* **차별화된 방법론 명명:** 당신들이 개발하거나 발견한 프로세스에 **고유한 이름(예: 'ABC 3단계 최적화 프레임워크')**을 붙여서, 이것이 '우리만의 방법론'임을 각인시키세요.
